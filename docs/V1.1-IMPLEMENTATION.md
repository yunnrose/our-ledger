# Our Ledger v1.1 implementation notes

## Scope
- Preserve the existing Realtime Database paths `transactions/` and `logs/`.
- Keep the chat-first interaction model and the two fixed members: 佩筠 and Benson.
- Use integer TWD amounts for calculations.
- Net-balance convention: positive means 佩筠 owes Benson; negative means Benson owes 佩筠.
- Pending expenses are excluded from confirmed totals and settlement.
- Expenses default to equal split; `advance` means the non-payer bears the full amount.
- Settlement rows carry both `payer` and `receiver`; old rows that only have `payer` are interpreted by the legacy rule (Benson payer => Benson pays 佩筠; 佩筠 payer => 佩筠 pays Benson).

## Authentication plan
1. Create two Firebase Authentication Email/Password users, one per person.
2. Map the authenticated Firebase UID to a fixed member identity in Realtime Database (server-managed allowlist).
3. Never trust a browser-selected display name as authorization.
4. Require authentication and allowlisted UIDs in Realtime Database Security Rules before enabling protected writes.
5. Do not deploy restrictive rules until both UIDs are registered and the current rules have been exported.

The current repository only contains a Realtime Database URL; it does not contain the Firebase Web App config required by Firebase Authentication (`apiKey`, `authDomain`, `projectId`, `appId`). These values must be copied from Firebase Console > Project settings > Your apps. They are configuration, not passwords, but must not be guessed.

## Data protection / rollout
- Export the complete Realtime Database JSON before migration.
- Keep the export outside this public repository.
- Work on branch `v1.1-auth-and-ledger-core`; do not overwrite the production branch until tests pass.
- Test against a separate Firebase project or isolated test data.
- Preserve existing transaction IDs and legacy fields.
- Keep audit events append-only; do not log passwords or authentication tokens.
- Roll back by restoring the previous deployment and, only if data migration occurred, importing the pre-change JSON backup.
